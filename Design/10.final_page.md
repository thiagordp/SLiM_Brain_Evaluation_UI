Yes. This page should be **much shorter and more functional** than the current screenshot.

The workbook already has a `Summary` sheet whose purpose is a roll-up of the Claim evaluations, not a new evaluation instrument.  That is exactly how I would treat this UI page: **no new substantive questions; only validation, navigation, and a concise summary of what the evaluator has already recorded.**

The meetings also support the dynamics we fixed earlier: the evaluator can save, leave, return, and revise the paper; completing a paper is provisional. Only the later **final submission of the whole Training/Evaluation set** makes the responses immutable.

## 1. Rename the page

I would use:

# Review paper

Subtitle:

> **Check that the evaluation is complete before marking this paper as complete. You can return to any section to review or change your responses.**

Avoid **Final review** or **Final submission** here. This paper is not yet being irreversibly submitted.

---

# 2. Overall status at the top

Instead of immediately listing dozens of individual criteria, begin with a compact summary.

For example:

### Evaluation status

**Incomplete — 6 items require attention**

Then a progress bar.

Below it:

| Section                   | Status                     |
| ------------------------- | -------------------------- |
| Source                    | ✓ Complete                 |
| Claims                    | ⚠ 13 of 14 Claims complete |
| Datasets                  | ✓ Complete                 |
| CITES                     | ⚠ 1 item incomplete        |
| Source-level completeness | ⚠ 2 items incomplete       |

Each row should be clickable.

This gives the evaluator the answer to the first question:

> **What is still missing?**

without requiring them to scan the entire page.

---

# 3. “Items requiring attention” should be the main section

This should appear immediately after the summary.

## Items requiring attention

> **Complete the following items before this paper can be marked complete.**

Then only show actual problems.

For example:

```text id="x3q2n3"
Claim CLM-0004-006
HE-06 · Textual grounding
No response selected.
                                      [Go to item]

Claim CLM-0004-009
HE-20 · Concept completeness
“In part” selected, but the missing Concepts have not been listed.
                                      [Go to item]

DST-0004
HE-15.4 · Size
“No” selected, but the required comment is empty.
                                      [Go to item]

CITES
HE-18.3 · Missing or spurious CITES edges
Required because HE-18.2 was marked “In part”.
                                      [Go to item]
```

This is much better than reproducing every criterion in a giant checklist.

### What counts as incomplete

The page should detect at least:

* no answer selected for a required criterion;
* **In part** or **No** with the required comment missing;
* conditional free-text field missing:

  * HE-18.3;
  * HE-19.3;
  * HE-20.b;
  * source-level missing Concept field, if we retain it;
* an applicable edge judgment not completed;
* an applicable Dataset question not completed.

This follows the workbook's principle that recall criteria store **what is missing**, not what is present, and that comments accompany negative/uncertain judgments.  We are simply applying the meeting-updated scale of **Yes / In part / No**.

---

# 4. Distinguish two kinds of “missing”

This is important.

The page currently risks mixing:

### A. Missing **evaluation data**

Things the evaluator forgot to answer.

Example:

> HE-06 has no response.

### B. Missing **Brain content identified by the evaluator**

Things the evaluator has correctly recorded as defects.

Example:

> Missing central Claim identified in HE-19.3.

The second one does **not** mean the evaluation is incomplete.

So I would create a separate section:

## Recorded omissions and defects

> **These are findings you recorded during the evaluation. They do not prevent completion if all required fields are filled.**

For example:

### Missing Claims

* “The paper additionally argues that …” — p. 12

### Missing Concepts

* `CPT-access-to-justice`

### Missing Dataset nodes

* Quebec annotated pathway comparison set — Section 4

### Missing / spurious CITES

* Missing: `SRC-0023`
* Spurious: `SRC-0011`

This is a useful final sanity check.

The evaluator can see:

> “Yes, those are really the defects I intended to record.”

But they are not asked to evaluate them again.

---

# 5. Completed sections should be collapsed

After the incomplete-items area, provide:

## Evaluation overview

Use one collapsible block per section.

### Source ✓

`2/2 complete`

### Claims ⚠

`13/14 Claims complete`

When expanded:

```text id="39clp5"
CLM-0004-001  ✓ Complete
CLM-0004-002  ✓ Complete
CLM-0004-003  ⚠ 1 item missing     [Open]
...
```

Do **not** display all 15 criteria for all Claims by default, as the current page appears to do.

That is why the screenshot becomes extremely long.

If a Claim is expanded, then show its compact results:

| Criterion | Answer  |
| --------- | ------- |
| HE-03     | Yes     |
| HE-25     | Yes     |
| HE-04     | In part |
| …         | …       |

The workbook's Summary tab already follows this kind of one-row-per-Claim roll-up logic. 

---

# 6. Do not turn this into an error-score dashboard

I would **not** show things like:

* “8 No answers” prominently;
* percentage of criteria passed;
* overall paper score;
* red/green quality rating.

The human evaluation is recording whether the **Brain representation** complies with the criteria, not grading the publication. The workbook explicitly says not to grade the paper. 

A `No` answer is a completed evaluation response, **not an incomplete task**.

So:

> **No = defect found, but evaluation complete.**

This distinction should drive the whole Review page.

---

# 7. Navigation from missing items

Every incomplete item needs:

**Go to item**

Clicking it should:

1. navigate directly to the relevant Source / Claim / Dataset / CITES / Recall page;
2. open the relevant section if the page has collapsible subsections;
3. ideally scroll directly to that criterion.

After fixing it, the evaluator can use:

**Return to Review**

This is one of the few places where direct jumping around the evaluation is desirable.

---

# 8. Marking the paper complete

When there are missing items:

### Paper status

**Incomplete**

> **6 required items still need attention.**

Disabled:

**Mark paper complete**

When everything is filled:

### Paper status

**Ready to complete**

> **All required evaluation fields are complete. You may still return to any section and review your responses before marking the paper complete.**

Button:

**Mark paper complete**

I would not require a scary confirmation here, because this is not irreversible.

A simple confirmation can say:

> **Mark W0085 as complete?**
> You can still reopen and revise this paper until the final submission of the Training set.

`Cancel` · **Mark complete**

---

# 9. After marking complete

Return directly to the **All papers** page.

The card becomes:

> **Complete**
> `[Review]`

The evaluator can reopen it and change answers.

If they change something so that a required response becomes incomplete:

> paper status automatically returns to **In progress**.

This keeps the state truthful.

Only when **every assigned paper is complete** does the separate All-papers page enable:

**Final submission**

And *that* is the irreversible action we already designed.

---

## Main principle

The current screenshot appears to treat Review as a **very long reproduction of the whole evaluation**.

I would instead make it a **validation dashboard**:

> **What is incomplete? → take me there → what defects did I record? → mark paper complete.**

That is simpler, safer, and much more consistent with both the workbook's roll-up structure and the submission dynamics we established in the meetings.
