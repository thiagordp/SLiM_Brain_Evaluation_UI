# A. Dataset node

## HE-14.1 · Warranted Dataset node

Current wording is rather technical.

### Question

> **Does this Dataset node correspond to a dataset, benchmark, or corpus that the Source actually uses or introduces?**

### Criterion definition

**How to judge**

> A Dataset node is warranted only when the Source actually **uses or introduces** the dataset, benchmark, or corpus.
>
> Do not count:
>
> * a passing mention;
> * a dataset mentioned only in related work;
> * a dataset belonging to a cited publication but not used by this Source; or
> * a dataset that the Source merely discusses.
>
> A Dataset node should exist when the Source's relationship to it warrants a `USES` relation.

This is a cleaner rendering of the existing HE-14.1 definition.

## HE-14.2 · Introduced by / used by

### Question

> **Do `introduced_by` and `used_by` correctly represent how this Dataset relates to the Sources in the Brain?**

### Criterion definition

> `introduced_by` identifies who introduces the Dataset:

# B. Dataset attributes

I would place a small heading here:

## Dataset attributes

> **Evaluate whether each attribute accurately represents the Dataset as described by the Source. Do not infer information that the Source does not provide.**

Then the seven criteria.

---

## HE-15.1 · Language

### Question

> **Does `language` correctly identify the language or languages of the texts in this Dataset?**

### Criterion definition

> `language` records the ISO 639-1 code or codes of the texts contained in the Dataset, as supported by the Source.
>
> Judge the language of the **Dataset contents**, not the language in which the paper itself is written.

That final distinction is worth making explicit.

---

## HE-15.2 · Jurisdiction

### Question

> **Does `jurisdiction` correctly identify the legal system or systems from which the Dataset's texts come?**

### Criterion definition

> `jurisdiction` describes the legal origin or scope of the **Dataset's contents**.
>
> It is different from:
>
> * `source_jurisdiction`, which concerns the publication; and
> * `claim_jurisdiction`, which concerns an individual Claim.
>
> Jurisdictions use the same coding convention as Claim jurisdictions, such as country codes, `EU`, `CoE`, or `INT`. 

This distinction will avoid a very predictable evaluator error.

---

## HE-15.3 · Document types

### Question

> **Does `document_types` correctly describe the kinds of documents contained in the Dataset?**

### Criterion definition

> `document_types` describes what the Dataset's texts or items are.
>
> Examples include:
>
> `judgments` · `statutes` · `contracts` · `exam questions` · `synthetic`
>
> The recorded value should reflect the Dataset as described by the Source rather than introduce a broader or different category. 

---

## HE-15.4 · Size

### Question

> **Does `size` correctly reproduce the Dataset size stated by the Source, including its unit?**

### Criterion definition

> Record the size as the Source states it, together with the relevant unit.
>
> Examples of units include:
>
> * documents;
> * cases;
> * questions;
> * sentence pairs;
> * tokens;
> * annotated items.
>
> Do not convert, estimate, or infer a different size when the Source does not provide it. 

---

## HE-15.5 · Annotation

### Question

> **Does `annotation` correctly describe how the Dataset was annotated?**

### Criterion definition

> The permitted values are:
>
> * `none` — no annotation;
> * `automatic` — annotation was produced automatically;
> * `human_single` — human annotation without multiple independent annotators;
> * `human_multiple` — annotation involved multiple human annotators.
>
> Judge the annotation process described by the Source. 

I would avoid the current very terse “Is annotation correct?” because it makes the evaluator search elsewhere to understand what the field means.

---

## HE-15.6 · Agreement reported

### Question

> **Does `agreement_reported` correctly indicate whether the Source reports an inter-annotator agreement measure for this Dataset?**

### Criterion definition

> The permitted values are:
>
> * `yes` — the Source reports an inter-annotator agreement figure;
> * `no` — inter-annotator agreement is relevant but no figure is reported;
> * `not_applicable` — inter-annotator agreement does not apply to the Dataset's annotation setup.
>
> This field records whether agreement is **reported**, not whether the reported agreement is high or satisfactory. 

That final sentence is particularly important. We are evaluating faithful representation, not grading annotation quality.

---

## HE-15.7 · Availability

### Question

> **Does `availability` correctly represent the Dataset's access status as reported by the Source?**

### Criterion definition

> The permitted values are:
>
> * `public` — publicly accessible;
> * `on_request` — available by request;
> * `proprietary` — access is restricted or proprietary;
> * `not_stated` — the Source does not state its availability.
>
> Judge what the Source reports. Do not infer availability from outside knowledge or from whether the Dataset can currently be found online. 

That last sentence keeps the evaluation grounded in the paper.

# 5. Important case: the Brain extracted no Dataset

The current Excel says to leave the Dataset sheet blank if the Source has none. 

The UI can do better.

If the Brain has no Dataset node:

```text
Datasets

The Brain created no Dataset nodes for this Source.

Dataset recall
HE-14.3 ...
```

Then still ask:

> **Has the Brain correctly represented all datasets used or introduced by this Source?**

This is essential; otherwise a Source where the Brain missed **every Dataset** would receive no Dataset evaluation at all.
